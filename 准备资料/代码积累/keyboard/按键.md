# MSPM0G3507 4×4 矩阵键盘操作手册

## 1. 本阶段的目的和范围

本手册用于指导在 CCS（Code Composer Studio）的 SysConfig 中，为工程 `empty_LP_MSPM0G3507_nortos_ticlang` 配置一个 4×4 矩阵键盘。

本阶段只完成 SysConfig 配置，不修改 `empty.c`，也不编写 `keyboard.c` 和 `keyboard.h`。完成配置并确认无误后，再进行键盘扫描、软件消抖、返回 1～16 键值以及 Watch 变量显示等代码工作。

当前工程使用的目标为：

- 开发板：`LP_MSPM0G3507`
- MCU：`MSPM0G3507`
- 封装：`LQFP-64 (PM)`
- 运行环境：NoRTOS
- 本机 MSPM0 SDK：`mspm0_sdk_2_10_00_04`

## 2. 接线与按键编号

| 键盘引脚 | MSPM0G3507 引脚 | 后续用途 |
| --- | --- | --- |
| R1 | PB7 | 行扫描输出 |
| R2 | PB6 | 行扫描输出 |
| R3 | PB0 | 行扫描输出 |

该键盘是无源开关矩阵，只需要上述 8 根信号线，不需要再给键盘接 3.3 V、5 V 或 GND。重新插拔杜邦线前，应先让开发板断电。

### 2.2 键值排列

根据 `硬件/键盘/R、C行列映射逻辑.png`，按键值按列递增，而不是常见的逐行递增：

|  | C1 / PB8 | C2 / PB15 | C3 / PB1 | C4 / PB12 |
| --- | ---: | ---: | ---: | ---: |
| R1 / PB7 | 1 | 5 | 9 | 13 |
| R2 / PB6 | 2 | 6 | 10 | 14 |
| R3 / PB0 | 3 | 7 | 11 | 15 |

后续 `keyboard` 函数将严格按此表返回 1～16。无按键时将另外约定返回值，不占用 1～16；具体返回类型和无键值会在代码阶段确定。

## 3. 扫描方式和电气逻辑

本项目采用“行输出、列输入、低电平有效”的轮询扫描方式：

1. R1～R4 配置成开漏 GPIO 输出，并通过内部上拉保持空闲状态为高电平。
2. C1～C4 配置成 GPIO 输入，并打开内部上拉，因此没有按键时读取为高电平。
3. 扫描某一行时，程序只把该行输出拉低，其他行保持释放状态。
4. 如果该行某个按键被按下，对应列会经按键与低电平行导通，程序会在该列读到低电平。
5. 扫描结束后把该行重新置高；开漏输出在置高时实际上是释放引脚，由上拉电阻将其维持为高电平。

行输出使用开漏（SysConfig 中可能显示为 `Hi-Z` 或 `High-Impedance/Open-Drain`）的原因，是避免同时按下多个按键时，不同行的推挽输出形成高、低电平直接对冲。它不能消除无二极管矩阵的多键“鬼键”现象，因此初版驱动以一次识别一个键为目标。

GPIO 不使用中断。矩阵键盘需要程序依次激活四行，轮询扫描比列中断更直接。按键机械抖动将在后续 `keyboard.c` 中通过延时和二次确认处理，GPIO 的输入迟滞不能替代软件消抖。

## 4. 打开 SysConfig

1. 在 CCS 的 **Project Explorer** 中展开工程 `empty_LP_MSPM0G3507_nortos_ticlang`。
2. 双击工程根目录下的 `empty.syscfg`，等待 SysConfig 图形界面加载完成。
3. 确认界面顶部或器件信息区域显示 `MSPM0G3507`、`LQFP-64 (PM)` 和 `LP_MSPM0G3507`。
4. 如果 CCS 询问是否迁移 SysConfig 版本，先保留当前工程所用的 MSPM0 SDK 产品版本；不要改成其他 MSPM0 型号或封装。

当前 `empty.syscfg` 只有 Board/SYSCTL 的基础配置，没有 GPIO 模块，因此下面需要新增一个 GPIO 实例。

## 5. 新增 GPIO 模块和引脚组

1. 在 SysConfig 左侧 **Software** 区域找到 **GPIO**。
2. 点击 GPIO 右侧的加号（`+` 或 **Add**），新增一个 GPIO 实例。
3. 将 GPIO 实例名（Instance Name / `$name`）改为 `KEYBOARD`。
4. 将端口（Port）选择为 `PORTB`。八根键盘线全部位于 GPIOB。
5. 在该实例的 **GPIO Pin Configuration**、**Associated Pins** 或同义区域，把 GPIO 数量增加到 8。不同版本界面可能是点击八次加号，也可能是将 **Number of Digital I/Os** 设置为 8。
6. 按下一节的表格依次命名和配置 8 个引脚。建议固定使用 R1、R2、R3、R4、C1、C2、C3、C4 的顺序，方便检查生成的宏。

不要建立 8 个不同的 GPIO 模块实例；一个名为 `KEYBOARD` 的 GPIO 引脚组包含 8 个引脚即可。当前 SysConfig 1.28.0 会直接用实例名作为生成宏的前缀，因此本工程生成的是 `KEYBOARD_*`。

| ---: | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | R1 | PB7 | Output | SET / High | Pull-Up | Enable | Low | Disable | 不适用 | Disable | Disable |
| 2 | R2 | PB6 | Output | SET / High | Pull-Up | Enable | Low | Disable | 不适用 | Disable | Disable |
| 3 | R3 | PB0 | Output | SET / High | Pull-Up | Enable | Low | Disable | 不适用 | Disable | Disable |
| 4 | R4 | PB16 | Output | SET / High | Pull-Up | Enable | Low | Disable | 不适用 | Disable | Disable |
| 5 | C1 | PB8 | Input | 不适用 | Pull-Up | 不适用 | 不适用 | Disable | Disable | Disable | Disable |
| 6 | C2 | PB15 | Input | 不适用 | Pull-Up | 不适用 | 不适用 | Disable | Disable | Disable | Disable |

表中“Disable”也可能在界面中显示为未勾选、`None`、`No` 或 `Disabled`。保持相同含义即可。

### 6.2 R1～R4 行引脚的详细设置

逐个选择 R1、R2、R3、R4，并设置：

- **Pin Name**：分别为 `R1`、`R2`、`R3`、`R4`，只使用大写英文字母和数字。
- **Direction**：`Output`。
- **Initial Output Value / Initial Value**：`SET` 或 `High`。四行上电初始化后都必须处于释放的高电平状态。
- **Internal Resistor**：`Pull-Up`。
- **Hi-Z / High-Impedance / Open-Drain**：`Enable`。在 MSPM0 GPIO 配置中，启用 Hi-Z 输出特性对应开漏方式。
- **Drive Strength**：`Low` 或默认档。键盘只是低速逻辑信号，不需要高驱动强度。
- **Inversion**：`Disable`。
- **Interrupt**：不启用。
- **Wakeup**：不启用。

如果部分高级选项没有显示，展开 **Advanced Configuration**、**Output Configuration** 或 **Configure Additional Features**。必须确认 Hi-Z 已启用，而不是仅将普通推挽输出的初始值设为高。

### 6.3 C1～C4 列引脚的详细设置

逐个选择 C1、C2、C3、C4，并设置：

- **Pin Name**：分别为 `C1`、`C2`、`C3`、`C4`。
- **Direction**：`Input`。
- **Internal Resistor**：`Pull-Up`。这是列输入没有按键时能稳定为高电平的关键配置。
- **Inversion**：`Disable`。后续代码直接把读取到的低电平解释为按下。
- **Hysteresis**：`Disable`，保留默认值。机械抖动由软件处理。
- **Interrupt Enable**：取消勾选或 `Disable`。
- **Interrupt Polarity / Edge**：因为中断未启用，无需配置；保持默认值。
- **Wakeup**：`Disable`。

列引脚不要设置为悬空输入（`None` / No Pull），也不要设置为 Pull-Down，否则会与本手册的低电平有效扫描逻辑不一致。

## 7. 分配物理引脚

在每个 GPIO pin 条目的 **PinMux**、**Device Pin**、**GPIO Pin** 或 `$assign` 下拉框中完成下列分配：

| Pin Name | 必须选择的 GPIO |
| --- | --- |
| R1 | `PB7` |
| R2 | `PB6` |
| R3 | `PB0` |
| R4 | `PB16` |
| C1 | `PB8` |
| C2 | `PB15` |
| C3 | `PB1` |
| C4 | `PB12` |

注意事项：

- 选择的是端口名 `PBx`，不是开发板排针座的丝印序号，也不是 LQFP 封装的管脚序号。
- 每个 PB 引脚只能分配一次。SysConfig 出现红色冲突标记时，不要强行保存，应检查是否把同一个 PB 引脚分给了两个条目。
- 不要启用这些引脚的 UART、I2C、SPI、Timer、ADC 等复用功能；功能保持普通数字 GPIO。
- 这些引脚没有占用 SWD 调试接口，因此本配置不会主动关闭调试端口。

## 8. SYSCTL 和其他模块

本次不需要修改现有 SYSCTL 配置，也不需要添加 Timer、Clock、NVIC、DMA 或其他外设模块。

保留工程现有设置即可：

- `forceDefaultClkConfig = true`
- 系统使用工程默认时钟配置
- NoRTOS 保持不变

键盘消抖和行切换后的稳定等待将在后续代码中使用 DriverLib 延时完成，不要求为了键盘单独配置硬件定时器。

## 9. 保存、生成和编译前检查

1. 按 `Ctrl+S` 保存 `empty.syscfg`。
2. 确认 SysConfig 页面没有红色错误标记，CCS 的 **Problems** 窗口中没有新的 SysConfig error。
3. 右键工程并选择 **Build Project**，让 SysConfig 重新生成 `ti_msp_dl_config.c` 和 `ti_msp_dl_config.h`。
4. 不要手工修改自动生成的 `ti_msp_dl_config.c/.h`；以后修改 GPIO 参数仍应回到 `empty.syscfg`。
5. 编译后可打开生成的 `ti_msp_dl_config.h`，检查是否存在以下宏。IOMUX 后面的具体数值由 SysConfig 自动计算，不需要手填：

```c
KEYBOARD_PORT
KEYBOARD_R1_PIN
KEYBOARD_R2_PIN
KEYBOARD_R3_PIN
KEYBOARD_R4_PIN
KEYBOARD_C1_PIN
KEYBOARD_C2_PIN
KEYBOARD_C3_PIN
KEYBOARD_C4_PIN
```

6. 可在生成的 `ti_msp_dl_config.c` 中做只读检查，应能看到以下含义的初始化：

   - R1～R4 使用数字输出特性初始化；
   - R1～R4 为 `PULL_UP`、低驱动强度并启用 `HIZ`；
   - R1～R4 在使能输出前先被 `set` 为高；
   - C1～C4 使用带 `PULL_UP` 的数字输入初始化；
   - 没有为键盘引脚使能 GPIO interrupt。

生成代码中的函数名、换行和引脚合并方式可能不同，只要实际含义与上述项目一致即可。

## 11. 常见问题

### 11.1 SysConfig 中找不到 Hi-Z

先确认该引脚已经设置为 Output，再展开输出的高级配置。MSPM0 的该选项可能叫 `Hi-Z`、`High-Impedance`，其生成结果应为 `DL_GPIO_HIZ_ENABLE`。如果界面仍没有该项，先不要改成普通推挽输出，请记录 CCS、SysConfig 和 MSPM0 SDK 版本以及界面截图，以便在写代码前确认。

### 11.2 保存后出现引脚冲突

检查八个 GPIO 条目是否有重复分配，并检查工程中是否已有其他外设占用了 PB0、PB6、PB7、PB8、PB12、PB15、PB16 或 PB1。当前原始 `empty.syscfg` 没有这些外设配置，正常情况下不会冲突。

### 11.3 编译后没有 `KEYBOARD_*` 宏

通常是 GPIO 实例名没有设为 `KEYBOARD`、SysConfig 没有保存，或者构建时没有重新运行 SysConfig。先保存 `empty.syscfg`，再执行 **Clean Project** 和 **Build Project**，然后检查实际参与编译的生成目录。

### 11.4 为什么暂时不用 GPIO 中断

单个独立按键适合边沿中断，但矩阵键盘必须主动切换行电平才能确定行列坐标。轮询扫描更容易实现稳定的键值、消抖和按住不重复触发，初版也更便于通过 Watch 调试。
